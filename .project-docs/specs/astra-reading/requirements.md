## 1. 배경과 범위

책장·책 메타데이터 편집·플레이어와 로컬 저장 기반은 있다. 페이지 제작 화면이 없어 신규 사용자가 한 권을 완성하지 못한다. 0단계는 UX, 디자인 토큰, 상태와 수락 기준, 단계별 종료 조건을 정의한다. 앱 구현·스키마 변경·배포는 후속 단계다.

컨셉은 **부모의 목소리가 담긴 작은 도서관**. 아이가 고르고 듣는 화면과 부모가 만드는 화면을 분리한다. 공개 서비스·소셜·랭킹은 범위에 없다. 외부 이미지·폰트·실제 아동 데이터 없이 합성 예시로 시안을 제공한다.

## 3. 수락 기준

- R-01. WHEN 책장을 열면 THE SYSTEM SHALL 검색·출판사 배지·출판사→전집→번호와 책 제목 트리 및 항목별 관리 메뉴를 제공한다.
- R-02. WHEN 읽기 이력이 없으면 THE SYSTEM SHALL 가짜 이어 읽기를 만들지 않고 책 선택을 안내한다.
- R-03. WHEN 읽을 책이 없으면 THE SYSTEM SHALL 빈 책장 안내와 보호자 진입을 제공한다. 샘플 책을 실제 보유 데이터로 저장하지 않는다.
- R-04. WHEN 보호자가 책을 만들면 THE SYSTEM SHALL 출판사·전집·번호·제목과 페이지별 사진·녹음을 한 화면에서 편집한다. 글·기기 읽기·순서 변경은 펼침 옵션으로 제공한다.
- R-05. WHEN 기기 읽어주기를 선택하면 THE SYSTEM SHALL 본문·해당 언어 엔진의 온디바이스/오프라인 사용 가능 여부를 확인한다. 네트워크 의존 음성이거나 오프라인 여부를 확인할 수 없으면 사용하지 않는다. 사용할 수 없으면 녹음 또는 글/엔진 설정을 안내한다.
- R-06. WHEN 사진·녹음 권한을 거부하면 THE SYSTEM SHALL 입력 내용을 보존하고 권한 안내·재시도·돌아가기를 제공한다.
- R-07. WHEN 제작 입력이 바뀌면 THE SYSTEM SHALL 유휴 900ms 후 초안을 자동 저장한다. 뒤로 갈 때 마지막 변경을 저장하고 실패하면 입력과 화면을 유지한다.
- R-08. WHEN 책을 아이 책장에 넣으면 THE SYSTEM SHALL 제목·페이지 사진과 페이지별 사용 가능한 음성을 검증한다. 미완성 책은 책장 메뉴의 만들던 책에서 이어 만든다.
- R-09. WHEN 앱 내부 화면이나 탭을 이동하면 THE SYSTEM SHALL 공통 재생목록의 재생을 유지한다. 서비스 준비 성공 시 앱 비활성화/화면 잠금에도 계속 재생한다. 통화·이어폰 분리·책 편집 진입에는 일시정지하며 복귀 후 자동 재생하지 않는다. 서비스 준비 실패 시 전경 재생으로 제한한다.
- R-10. WHEN 음원/사진이 사라지면 THE SYSTEM SHALL 빈 파일을 정상 재생으로 처리하지 않고 복구 안내를 보여준다. 텍스트와 엔진이 있는 경우에만 TTS 폴백한다.
- R-11. WHEN 만들던 책·플레이리스트 편집에 진입하면 THE SYSTEM SHALL 보호자 확인을 거친다. 이는 우발 조작 방지이며 인증·보안 경계로 주장하지 않는다. (2026-09-20 개정: 책 등록·편집은 확인 없이 연다 — §책 등록 화면 개편)
- R-12. WHEN 화면 폭·글자 크기·테마가 바뀌면 THE SYSTEM SHALL 주요 조작을 가리지 않고 텍스트와 색 이외의 상태 표시를 유지한다.

## 4. 제약과 검토 지점

- provider / get_it / go_router 및 로컬 JSON·미디어를 유지한다. 스키마 변경은 1단계에서 호환성 검증 후 진행한다.
- M1 로컬 MVP에는 로그인 요구를 제거한다. Google 인증은 클라우드 연결 직전에 구현한다.
- AI는 후속 단계(M3)이며 기기 밖 클라우드 AI 는 쓰지 않는다. 처리자는 미정이다(2026-10-05 101 워커 폐지 — M3 착수 시 재설계). OCR은 편의 단계이며 MVP 필수 아님.
- Firebase 전송은 외부 AI 처리와 다르다. 도입 전 데이터별 업로드·잔존·삭제 범위를 설명해야 한다.
- 단계마다 결과를 제시하고 검토 지점에서 멈춘다. 다음 단계는 사용자 지시로 착수한다.
- 2026-09-19 사용자 결정으로 5단계 제작과 별도 부모 공간 중심 UI를 폐기하고 음악 앱형 메뉴 구조로 개편한다. 실기기 기능 테스트는 사용자 요청으로 보류한다.

## 5. 음악 앱형 UI 추가 수락 기준 (현행)

- R-13. 하단은 책장/플레이리스트/최근재생목록/설정. 책 만들기는 책장 + 또는 전집 메뉴에 둔다.
- R-14. 저장 Playlist는 생성·이름 변경·삭제·책 추가/제외·순서 변경이 가능하다. 삭제해도 원본 책은 유지한다.
- R-15. PlaybackQueue는 저장 Playlist와 별개다. 재생/전체 재생은 현재 큐를 교체하고 시작하며, 큐 추가는 기존 재생을 유지하고 뒤에 추가한다. 같은 책 중복 추가는 하지 않는다.
- R-16. 공통 큐는 현재 책/페이지·재생/일시정지·순서 변경·항목 제거·비우기를 제공한다. 끝난 책 다음에는 큐의 다음 책을 재생하고, 마지막에서 멈춘다. 현재 책 제거는 멈추고 다른 책을 임의로 시작하지 않는다.
- R-17. 게시한 책이 큐에 있으면 해당 항목을 갱신하고 구판 플레이어를 폐기한다. 새 판은 사용자가 다시 재생할 때 시작한다.
- R-18. 출판사 배지는 실제 등록 책에서 구성한다. 검색은 출판사/전집/책 제목에 적용한다. 미분류 책도 표시한다. 연령(4–7세/8–11세 등) 분류 전환은 후속 범위로 기억한다.
- R-19. 전집에서 책 추가 시 출판사·전집을 미리 채우고 기존 최대 권 번호+1을 제안한다. 최근재생목록의 ID·순서·현재 책을 로컬에 저장하고 재시작 시 복원하되 자동 재생하지 않는다. 저장 Playlist와는 별도다.

## 6. 아기자기한 표현 보완

2026-09-20 사용자 요청: 정적인 인상을 줄이고 아기자기한 느낌으로 진행. 하단 탭/트리/저장 Playlist와 현재 큐의 계약은 유지한다. 캐릭터·부드러운 색과 한 번의 상호작용 애니메이션을 사용하며 반복 애니메이션은 추가하지 않는다. 동작 줄이기·밤 테마·큰 글자에서 조작을 보존한다. 실기기 기능 테스트 보류는 계속 유효하다.

## 2-1 백업·복원 기반

- 앱이 쓰기를 멈춘 상태에서 library/index/drafts/reading_positions의 메타·미디어를 함께 복사한다. 최근재생목록도 index/recent_playback.json에 저장되므로 함께 포함한다.
- 원본 바이트를 보존하고 SHA-256으로 파일 수·길이·내용을 검증한다. 손상/미래 JSON도 원문을 보존하며, 파일 무결성과 앱에서 읽을 수 있는지는 구분한다.
- 기존 대상은 빈 디렉터리라도 덮어쓰지 않는다. 활성 앱 데이터와 분리된 새 경로에서만 복원한다.
- 링크·경로 순회·중복·상한 초과·manifest 불일치는 거절한다. 작업 중 임시 파일이나 원본 변화는 재시도 대상으로 처리한다.
- 이번 하위 단계는 저장소 API/DI/실제 파일 검증까지다. 설정 UI, 모바일 파일 선택, 단일 파일 번들, 암호화, 실행 중 저장 차단과 활성 데이터 교체는 2-2에서 설계·검증한다.

## 공통 플레이어·백그라운드 재생 (2026-09-20)

- 책장/플레이리스트/최근재생목록에서 시작해도 같은 PlaybackQueue와 플로팅 플레이어를 사용한다. 재생 시작만으로 화면을 이동하지 않는다.
- 플로팅 확장 패널과 최근재생목록 탭은 같은 QueuePanel을 사용한다. 목록 순서·제거·비우기와 책 펼치기/재생·정지/이전·다음 책을 관리한다.
- 최근재생목록은 마지막으로 구성한 재생 순서이며 누적 청취 통계가 아니다. 최대 1,000권, 중복 없이 관리하고 삭제된 책은 재시작 복원 시 제외한다.
- Android 미디어 서비스와 iOS audio background mode를 구성한다. 알림/잠금화면 play/pause/stop/이전·다음 책은 같은 큐 명령으로 연결한다. 외부 앱 위에 떠 있는 오버레이 권한은 요청하지 않는다.
- 편집/녹음 화면이 열려 있는 동안 OS에서 보낸 재생 명령도 차단한다. 최근 앱 목록에서 앱을 밀어 닫으면 재생을 종료한다. 강제 종료 뒤 자동 재생하지 않는다.
- 사용자 요청에 따라 실기기 검증은 보류하며, 백그라운드/잠금화면의 실제 OS 동작은 미확인으로 표시한다.

## 책 등록 화면 개편 (2026-09-20)

책장 ＋에서 부모 공간을 거치지 않는다. 출판사 선택, 전집·책 번호 필수. 저장 버튼 하나로 책장 반영. 표지 촬영과 내용 촬영을 별도 영역으로 제공하고 표지를 본문 페이지로 취급하지 않는다.

## 본문 가로 연속 촬영 (2026-09-20)

본문은 가로 화면에서 여러 면을 연속 촬영하고 완료 때 제작 화면으로 돌아간다. 펼친 책 좌우 면이 사진 하나/재생 페이지 하나다. 장수 표시·매 장 즉시 보관·실패 사진 재시도/제외 확인을 제공한다. 표지는 단일 촬영을 유지한다.

## 사진 제작과 자르기·보정 (2026-09-20)

책 만들기에서는 녹음/들어보기를 제거하고 사진 제작에 집중한다. 음성은 별도 책 메뉴에서 편집한다. 사진만으로 책 저장 가능. 표지/내용 사진 모두 촬영 후/기존 사진에서 수동 사각형 자르기와 밝기·대비 보정을 지원하고 원본 색상 선택을 제공한다. 기존 음성 트랙을 훼손하지 않는다.

## 2-2 단계 분리 (2026-09-22)

2-2a는 Android 로컬 단일 파일 저장과 선택한 파일의 무결성 검사다. 가족 자료의 외부 자동 전송은 없고 비암호화임을 알린다. 취소/실패 시 현재 책장을 유지하고 잠금을 해제한다. 2-2b는 안전한 현재 책장 교체이며 별도 후속 구현이다. 검사 UI가 복원 완료로 오인되지 않아야 한다.

## 2-2b 수락 기준 (2026-09-28)

Android 백업 파일 선택 → 무결성/메타데이터/미디어 참조 검증 → 책/플레이리스트/초안 개수 및 전체 교체 확인 → 활성 책장 반영. 취소/검증 실패는 기존 자료 유지. 교체 중 실패/프로세스 종료는 pending 저널 원복, 확정 후는 새 자료 유지. 복구 실패 시 쓰기·재생·이탈을 막고 재시작 안내. 기존 앱이 지원하는 구형 raw JSON도 엄격 검증하여 복원 가능해야 한다. 현재 최근목록이 손상돼도 정상 백업 복원 진입은 가능해야 한다.

## OS 클라우드 백업 차단 (2026-10-06)

오너 결정 [A-06-7]. 앱 데이터(사진·녹음·기록)는 iCloud·Google 드라이브 자동 백업과 Android 기기 이전에 실리지 않아야 한다.
기기 밖 보관은 사용자가 고른 `.mcrb` 파일로만 한다. iOS 는 백업 경로가 없는 상태(기기 분실 = 데이터 손실)를 오너가 수용했다.
